# FleetIQ test deployment

The local preparation package is `build/public-preparation/`. **Do not upload it yet:** the confirmed domain has not been supplied, so its sitemap is empty and robots disallows crawling. No domain or sender has been invented.

1. Confirm the host, HTTPS domain and any installation subdirectory. Code minimum: PHP 8.1. Recommended deployment: latest patched PHP 8.4, the branch tested locally. PHP 8.1 is unsupported; check [PHP support status](https://www.php.net/supported-versions.php). Sessions, filter, JSON and working PHP `mail()`/hosting mail are required; no database is needed.
2. Set `FLEETIQ_SITE_URL` to the actual HTTPS base URL without a trailing slash, including the subdirectory if applicable. Set the **same value** during packaging and on the server. Set `FLEETIQ_DEMO_FROM` to the actual provider-authorised sender mailbox. Retain recipient `iancrofts@live.co.uk`; no recipient override is needed. Use `FLEETIQ_DEMO_TRANSPORT=mail` when ready to test delivery. No credentials belong in public files.
3. If the host cannot supply environment variables, copy `tools/config.example.php` to `fleetiq-config.php` immediately above the document root, in a genuinely private directory, and edit the private copy. `FLEETIQ_CONFIG_FILE` can specify another private absolute path. See README for environment precedence and access restrictions.
4. With the actual URL configured in the local shell, run `php tools/build-public.php build/public-test`. The destination must not already exist; choose a new name for subsequent builds. Upload **only the contents** of that newly generated directory, including `.htaccess` and `.user.ini`.
5. Configure HTTPS redirects, private writable logs/sessions and PHP settings: `display_errors=Off`, `display_startup_errors=Off`, `log_errors=On`, `expose_php=Off`. Ensure PHP correctly recognises HTTPS so contact session cookies are Secure. The generated `.user.ini` requires CGI/FastCGI support; otherwise use the host's PHP settings.
6. Apache 2.4: confirm `.htaccess` access rules and `ErrorDocument 404` are supported. Nginx/other hosts must apply equivalent access rules and internally route unknown requests to `404.php`, preserving HTTP 404. README includes the configuration outline. Deny hidden files and direct access to `includes/` and `components/`; disable directory listings. The local PHP router does not verify real Apache/Nginx enforcement.
7. Open all 12 content pages. Inspect each canonical and `og:url`; they must use the configured public base URL. Fetch `/sitemap.xml`: 12 intended routes, no 404, no local/reserved URLs. Verify `/robots.txt` references that sitemap. Adjust the paths for subdirectory hosting.
8. Open an unknown nested URL and `/404.php`: expect HTTP 404, the branded message and working Home/Explore links, `noindex`, and no canonical. Verify hidden/configuration files, includes/components, tests and archives cannot be read over HTTP.
9. Test required/optional fields, invalid email, safe retained values, error focus and retry. Missing/failed mail must show an honest generic failure. Once authorised for an end-to-end delivery test, submit one enquiry and verify receipt at `iancrofts@live.co.uk`, Reply-To and spam placement. Refresh must not resend. A successful `mail()` return proves transport acceptance only; actual delivery depends on the host and sender authentication.
10. Confirm operator identity/contact information, hosting/mail providers, processing locations, retention and the enquiry processing basis before inviting public enquiries. Update Privacy with confirmed specifics. Complete Firefox/Safari, real mobile and assistive-technology checks; local Chrome checks are recorded in `PHASE4-REPORT.md`.

The 40-file preparation manifest is `build/package-manifest.txt`, outside the public folder. Only the explicit `tools/public-files.php` allowlist plus six generated server/SEO files enter a package. Never upload `.git`, `.codex`, `.agents`, tests, tools, fixtures, screenshots, logs, README, VALIDATION, this guide/report, archives (including `README.zip` or `workshop.zip`), temporary files or private configuration. Keep all source files in the repository.
